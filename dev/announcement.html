Relaunching Interactive Safety Graphics

Draft for discussion, 9 November 2026. The text is the working draft of the blog post; it is not final and has not been sent.

Background

The Interactive Safety Graphics (ISG) working group started around 2018, as a workstream of the ASA Biopharmaceutical Section's Safety Scientific Working Group with DIA. Together, members from industry, academia and the FDA built safetyGraphics: free, open-source interactive charts for reviewing safety data in clinical trials.

The project has been on hiatus since early 2021, but we’re excited to announce we're relaunching the group in early 2027. Here's what's changing, and what isn't.

What's not changing

The heart of the group is still the collaboration between clinical and technical groups who are passionate about modernizing clinical trials.

  • Clinicians and safety scientists say what a chart needs to show, and sign off on whether it shows it correctly. Jim Buchanan leads the clinical side.
  • Statisticians and developers build it. Jeremy Wildfire leads the technical side.
  • Membership stays open, the code stays open source (Apache 2.0), and members speak for themselves, not for their employers.

What's changing

1. Better Graphics

The core charts in safetyGraphics were built over 10 years ago and a lot has changed since then. That change has only accelerated in the last few years as AI coding agents have rapidly improved and made more ambitious projects possible without extensive resourcing and funding.

Jeremy and Jim started rebuilding safetyGraphics from the ground up using AI in 2026. You can read about that work in the recap of Jeremy’s 2026 R/Pharma Keynote. The new packages safety.viz (JavaScript) and gsm.safety (R) will serve as the foundation for the relaunched group. In 2027 the priority is firming up that new foundation and creating an AI-supported development model that will support expanding the framework to new domains.

2. AI Workflows + Human Experts

The way software is created is evolving rapidly (see METR's measurements of how long a task AI agents can finish, and the 2025 Stack Overflow developer survey). AI agents did all of the programming and much of the coordination for the updated versions of the graphics. Agents wrote and tested the code, turned feedback into tracked issues, organized demo data, drafted release notes and helped make the slides for the presentation.

While AI did a lot of work on the new version of the tools, Jeremy and Jim made the key decisions. Jim reviewed the graphics and pointed to papers and workflows documenting emerging clinical best practice. Jeremy set up the technical framework to embed critical evidence into the development process and support deployment in GxP frameworks.

The new working group will be run using agentic AI workflows driven by human expertise. It's all in the open. Every change an agent makes is a public pull request that says an agent drafted it and names the person who reviewed it. The next step is to scale this effort up from 2 people, to an entire working group. We need a simple intake process for clinician comments, contributor guidelines for multiple users (and their own AI agents), and many other process improvements to support these new ways of working.

3. Quality documentation built in

The first question we had when presenting the original version of the safetyGraphics tools was “Are they validated?”, and while we did our best to make sure the tools worked as expected, the honest answer to that question was “No, they’re exploratory.” The new version of the tools seek to improve on that.

We plan to embed formal quality gates in all parts of the new workflows. Both human and AI driven quality is part of the work, not an afterthought.

  • Every chart has written requirements, tests linked to those requirements, and an evidence page on the site showing which pass. There are nearly 3,000 tests in safety.viz alone right now (2,541 unit and 456 browser tests in v1.11.3).
  • Every chart carries a status (Qualified, Exploratory, Experimental or Prototype), so users know how far to trust it. None is Qualified yet; getting there is part of the 2027 work.
  • Clinical changes are signed off separately from code review, and every release has short release notes.

How can I contribute?

  • Try the tools: the demo app and gallery are on the safety.viz site. Tell us what's wrong, confusing or missing at contact link
  • Send feedback by email. You don't need GitHub: every request is logged and checked, and you'll hear back on what happened to it. How it works
  • Clinicians and safety scientists: review clinical changes before they're released.
  • Statisticians and developers: pick up a starter issue with the contributor guide (piloted this winter), or learn to run the agents for your own work.

Ready to re-join? Fill in the short interest form (link to come) and tell us how you'd like to contribute. We'll follow up with the details of the first monthly meeting in January.
